# 全链路审查报告（2026-10-13）

v3.0.13 ~ v3.0.17 连续快速迭代后的系统性审查。审查方式：静态代码审查 + 真实浏览器
动态走查 + 对照 React 原版（从重建前的备份 bundle 中提取）。

## 一、静态审查

### 1. 前端脚本初始化模式（重点：排查「孤儿脚本」类静默失效）

v3.0.16 刚修掉一个从 v3.0.0 起就存在的孤儿脚本（`admin-ai.js` 从未被加载，靠
`typeof window.setupAdminAi === "function"` 判断静默跳过）。本次逐文件复核全部
11 个脚本的初始化模式：

| 脚本 | 加载方式 | 初始化 | 元素缺失时 |
|---|---|---|---|
| api.js | 被 import | 无初始化 | — |
| app.js | layout 引入 | `setupMenu/setupLogout` 直接执行 | 内部逐个查询、逐个判空 |
| login.js | login.php 引入 | 表单绑定（函数内） | 逐个判空 |
| practice.js | practice.php 引入 | `void init()` | boot 缺失时 init 内部处理 |
| profile.js | profile.php 引入（两个互斥分支各一处） | 表单绑定 | 逐个判空 |
| collection.js | collection.php 引入 | `if (root)` 守卫 | 跳过 |
| admin.js | admin.php 引入 | `init()` + `import setupAiAssistant` | boot 缺失显式 throw |
| admin-ai.js | **admin.js import**（v3.0.16 修复） | 被 setupAiAssistant 调用 | root 缺失 return |
| admin-users.js | admin-users.php 引入（仅正常分支） | `if (root)` 守卫 | 跳过 |
| admin-system.js | admin-system.php 引入（仅正常分支） | `if (root)` 整段守卫 | 跳过 |
| flash.js | 被三个脚本 import | 无初始化 | — |

**结论：无第二个孤儿脚本。** 关键经验：`typeof window.xxx === "function"` + 全局挂载
的「约定式初始化」在脚本未加载时**静默失效**；ES module `import` 缺依赖会当场报错。

### 2. 接口契约核对

前端 `api.js` 的 26 个请求路径 vs `index.php` 的 32 条路由（含动态参数）：**一一对应，
无孤儿、无错配**。

### 3. 近期改动复核（v3.0.13 ~ v3.0.17）

退出码修复（proc_get_status）、自动生效/刷新/缓存戳、AI 助手 import、来源生成——
逻辑复核均正确，且已有对应测试。

## 二、动态走查（测试盲区补齐）

审查发现 **UI 测试此前对 3 个页面零覆盖**：用户管理页、系统设置页、以及录题后台的
全部数据操作。用真实浏览器（Playwright + Chrome）逐项走查，共 49 项。

### 2.1 真实缺陷（已修复）

**问题：操作成功提示被整页刷新冲掉（用户管理 6 操作 + 收藏页 2 操作 + 录题后台
6 操作）**

- 现象：管理员新建用户、重置密码、改角色、禁用、删除——服务端全部成功、列表正确
  更新，但**看不到任何成功提示**（提示出现后立即被 `location.reload()` 冲掉）。
  收藏页「取消收藏/取消标记」同样。录题后台的「恢复示例」「清空」则**原本就没有提示**。
- 对照 React 原版（`UserAdmin.tsx` / `Collection.tsx` / `Admin.tsx`）：原版为
  `setNotice(...)` + `load()`（SPA 内更新数据，**提示保留可见**），部分文案
  （"已恢复内置示例数据，共 X 道题、Y 个标签"、"已清空服务端数据"）在迁移中丢失。
- 修复：新增 `php/assets/js/flash.js`（sessionStorage 一次性提示，跨刷新传递），
  改造 3 个脚本共 9 处调用点；恢复示例/清空补上原版文案。
  **优先级不变**（手填来源 > JSON 自带 > "AI 生成"）。
- 隐私模式下 sessionStorage 不可用时静默降级（无提示，不影响主流程）。

### 2.2 无问题（甄别记录，避免未来重复误报）

| 疑点 | 结论 |
|---|---|
| 系统设置页没有「立即更新」按钮 | **设计如此**：按钮只在「发现新提交」时渲染；已是最新时不显示 |
| 新增标签后页面「看不到」新标签 | **测试脚本 bug**：标签名在 `<input value>` 里，`locator.filter({hasText})` 匹配不到；用属性选择器 `[data-tag]:has(input[value=...])` 后确认功能正常 |
| 删除题目后「题数对不上」 | **测试脚本 bug**：页面 DOM 是旧快照，应从接口取真实数量 |
| reload 后后台页签回到「手动精录」 | **设计如此**：页签状态不持久化（原版同） |
| 404 页返回 404 状态码（SPA 时代是 200） | **有意收紧**（v3.0.0 决策，页面内容一致） |
| favicon 404 | 原版同样存在，行为一致 |

## 三、测试覆盖扩充：94 → 128 项

走查的 35 项有效断言合并进 `php/tests/ui-test.mjs`（永久回归保护）：

- **404 页**：渲染 + 状态码（2 项）
- **收藏/标记取消**：flash 提示 + 列表减少（4 项）
- **录题后台数据操作**：删除题目（flash + 真实数量）、恢复示例（文案 + 数量）、
  标签启停翻转/恢复、新增/删除标签、清空 + 恢复（13 项）
- **用户管理页**：新建（含 flash）、重置密码（新密码登录验证）、改角色、禁用、
  删除（9 项）
- **系统设置页**：渲染、版本、PHP 版本、检查更新、已是最新时无更新按钮（5 项）
- **改密成功/退出/注册**：改密成功与改回、退出三态、注册成功与 token（8 项）

**当前测试基线**：接口 60/60、页面 128/128。

**测试环境注意**：ui-test 依赖全新库（断言从干净状态起步）；操作类断言统一用
「等待导航完成」而非固定延时；`confirm` 对话框在脚本里自动确认。
